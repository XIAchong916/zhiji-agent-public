## 1. What This Is

This is a **real end-to-end run** of the governed diagnosis Product Loop, using a fictional company (Qiyuan Technology) and a B2B lead-conversion diagnosis case. The recording starts from human-entered business context and proceeds until `PRODUCT_OUTPUT_READY`.

- Semantic generation uses a **real model** (TokenHub `hy3`), not pre-scripted deterministic fake content.
- The full run persists to PostgreSQL (Docker + Alembic at head), rather than an in-memory simulation.
- Every semantic gate is reviewed and confirmed by a human. The Agent never self-confirms or self-selects.

## 4. What Happens in the Full Engineering Demo

| Stage | What happens |
|---|---|
| Case intake | 24 human inputs: Case key, 12 Phase16 diagnosis inputs, and 11 Module17 business-case inputs |
| Governed entry | Decision proposal `PROCEED` → independent review `APPROVED` (two human gates) |
| Object confirmation | The OBJECT family is confirmed field by field by the human (object / type / business identity / objective) |
| Current Position | **No Agent draft is used**: `InternalState {R, θ, D, Ω}` remains USER-owned and is entered manually. The current interaction path cannot yet merge an Agent-drafted Position with USER-provided InternalState into one confirmation |
| Target Position | **Agent-drafted and confirmed**: `TargetPositionSnapshot` (`HYPOTHESIS`, stops at the USER Gate) |
| ChangeLaw | **Agent-drafted and confirmed**: `ChangeLaw` |
| Intervention | **Agent-drafted and confirmed**: `InterventionOption`, referencing the confirmed `ChangeLaw` ID in the current Journey |
| Solution selection | Two candidate solutions are shown → human `SELECT`s candidate #1 and records the rationale. **Candidates are assembled deterministically, not generated by the model** (`RealLLMProposalAdapter` is not used for this family) |
| Constraint review | Two hard constraints are explicitly confirmed as satisfied |
| Terminal state | `PRODUCT_OUTPUT_READY`, containing Business / Scenario diagnosis packages, a Solution package, and complete lineage |

## 5. Honest Boundaries — What This Demo Does Not Prove

- This video does **not** prove that the Agent can autonomously complete enterprise diagnosis. Every semantic gate is reviewed and confirmed by a human; the Agent only drafts proposals.
- It demonstrates that **a real model can produce Semantic Proposals within the defined governance boundary in this Demo path**. It does not prove stable, general enterprise-diagnosis quality.
- It contains **no real business-outcome validation**. The company is fictional; the metrics and evidence structure are internally coherent but are not real customer data.
- It does **not** claim production readiness. The output preserves the public governance boundary: `No execution: true` / `No authorization: true`.

## 6. Known Limitation

The current Current Position interaction has one explicit limitation:

- `R / θ / D / Ω` belong to USER-owned InternalState;
- the current flow cannot yet merge an Agent-drafted Position description with USER-provided InternalState in a single confirmation path;
- therefore the Current Position in this Demo is fully entered by the USER.

Planned interaction:

```text
Agent drafts Position
        ↓
USER supplements / corrects InternalState
        ↓
Merged confirmation
```
